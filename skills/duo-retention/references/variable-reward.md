# Variable Reward

## Concept

Variable-ratio reinforcement (B.F. Skinner) is the schedule that produces the most persistent behavior: a reward arrives, but not every time, and the user can't predict which time. Slot machines run on this. So do birds pecking levers. So does most engagement design done well.

The product question is not whether to use variable reward — it's how to use it without sliding into manipulation.

## What Duolingo does

- **Treasure chests / gem drops** appear after some lessons, not all. The user can't compute the expected value precisely.
- **League outcomes** depend on others' activity, so even consistent behavior produces variable rank.
- **Character cameos** (Lily appearing, Duo reacting in a new way) are intermittent surprises within an otherwise predictable flow.
- The base XP reward is *fixed* — variable reward is layered *on top* of a reliable baseline, not used as the baseline itself.

## The transferable pattern

Three rules for adding variable reward without becoming a casino:

1. **Layer it on top of a guaranteed reward.** Users should always know the base outcome of their action. Variability is the bonus, not the floor.
2. **The rare reward must be cheap to receive but emotionally rich.** A surprise character animation costs you nothing; a real-money payout breaks the model.
3. **Remove it the moment it stops mapping to the activity.** Slot-machine mechanics divorced from real progress are the boundary between *engaging* and *exploitative*. ([[../duo-gamification/references/anti-grind]])

A useful test: would you be comfortable if a 12-year-old's parent saw the mechanic and asked you to explain it?

## Apply to your product

- Does your product have any variable element, or is every outcome perfectly predictable?
- If you have variable reward, is it layered on top of a guaranteed baseline?
- Could a critic plausibly call your variable reward "manipulative"? If yes, what would you change?
